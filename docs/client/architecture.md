# Board Client architecture

Design draft · [Board Client](README.md) · [System map](../README.md) · [Development lifecycle](../engineering/lifecycle.md)

The Board Client is a presentation and control-plane interface over `CompanyDaemon`. It translates authorized projections into operator views and forwards explicit human decisions to the daemon's local Unix domain socket (UDS) Control Plane. The company operates, executes paper trades, reconciles fills, and recovers from crashes without the client installed or running.

## 1. Ownership boundaries

| Layer | Component | Authoritative ownership | Hard prohibitions |
| --- | --- | --- | --- |
| **Presentation** | React 19 + `@openboa/yogurt` (`0.2.0-local.1`) + `@ui-sdk/react` (`0.1.0-beta.13`) | Active route, local table sort/filter, `LinkState`, host-lock privacy shield, form drafts, inline `ControlledInlineConfirm` expansion state, `CommandOutboxPanel` display | Zero direct SQLite access; zero venue/exchange/owner keys or secrets in renderer; zero client-side P&L/return calculation; zero synthetic command receipts; zero right slide-over drawers (`Y.Sheet` prohibited); zero dimmed popup confirmation modals for routine approvals |

| **Control Plane** | `CompanyDaemon` (`src/sourdough/ipc/server.py`, `control-plane-v1`) | UDS kernel peer verification (`LOCAL_PEERCRED` / `LOCAL_PEERPID` / `SO_PEERCRED`), `board_binding` & `role_assignment` RBAC (`BACKEND_GAP #2`), `GET /v1/meta`, `GET /v1/projections/*`, `GET /v1/events`, `POST /v1/commands`, `GET /v1/commands/{command_id}?operation=...` (`35` concrete endpoints; see [Control plane intent](control-plane/intent.md)) | Never assumes a UI click equals an applied transition; never grants `board_control` solely from same-UID socket access; never routes Board 1:1 chat to non-CEO Agents |

Per-click CLI subprocesses (`sourdough client-bridge` or direct-store `inspect-work` / `read-command-receipt`) are prohibited in the target client. All reads and writes traverse `CompanyDaemon`'s resident UDS `/v1/*` Control Plane (`0o700` socket directory, `0o600` socket, `<= 103`-byte path limit).

## 2. Host topology and loopback HTTP-to-UDS bridge security

### 2.1 Primary standalone host (`sourdough client-web`, `[BACKEND_GAP #1]`)

Until a native WebView host passes capability verification, the primary host serves the React 19 `@openboa/yogurt` bundle via `sourdough client-web`, a local HTTP-to-UDS bridge that terminates browser HTTP on loopback and forwards exclusively to `CompanyDaemon`'s UDS socket:

- **Loopback bind only**: Listen strictly on `127.0.0.1:<ephemeral>` (never `0.0.0.0` or wildcard interfaces).
- **Strict `Host` and `Origin` pinning**: Reject any request whose `Host` header is not the exact bound `127.0.0.1:<port>` or `localhost:<port>`, or whose `Origin` / `Sec-Fetch-Site` indicates a cross-origin or DNS-rebinding caller, failing closed with `403`.
- **Out-of-band session authentication**: Prefer Mode 3b: a per-launch CSPRNG bearer token delivered out-of-band into host memory (stdin/FD/`0o600` bootstrap handoff) and sent via `Authorization: Bearer` (inherently origin- and port-bound). If Mode 3a (`HttpOnly; SameSite=Strict` session cookie via `fetch(..., { credentials: "same-origin" })`) is used, bind both the cookie name (`sd_sess_<ephemeral_port>_<instance_id>`) and the server-verified MAC payload explicitly to `(ephemeral_port, instance_id)` because browser cookies on `127.0.0.1` are host-scoped rather than port-scoped. Never pass tokens in URL query parameters (`?token=`) and never persist tokens in `localStorage` or `sessionStorage`.
- **`fetch()` NDJSON streaming (never `EventSource`)**: Consume `GET /v1/events?after_seq=<n>&limit=<k>&wait_ms=<ms>` (`application/x-ndjson`, `wait_ms <= 5000`, `Connection: close`, `Cache-Control: no-store`) via `fetch()` `ReadableStream` / bounded long-poll. Do not use `EventSource` because it cannot attach custom `Authorization` headers, cannot inspect structured HTTP `401`/`403`/`503` disconnect payloads before retrying, and cannot synchronize cleanly with `clearData()`.
- **Bridge-owned `0o600` `board-pending` persistence**: The bridge (not browser storage) owns write-ahead `LocalCommandIntent` persistence (`{company_id, principal_id, command_id, command_type, contract_version, preconditions, payload, payload_sha256, sent_ns}`, retaining `expected_revision` only if needed for legacy display) inside an `O_RDONLY | O_DIRECTORY | O_NOFOLLOW` (`0o700`) directory, writing atomic `O_CREAT | O_EXCL | O_NOFOLLOW` (`0o600`) files with `fsync(fd)` and `fsync(dir_fd)`, keyed strictly by **`(company_id, principal_id)`** (`{base_dir}/{company_id}/{principal_id_sha256}.json`). Persisting full canonical `preconditions` (including `charter_revision`, `expected_revision`, and all extended preconditions) plus `contract_version` ensures cold-start `Retry same ID` resubmits the exact original request without reading newer live revisions.
- **Explicit `LOCAL_PEERPID` collapse boundary**: `CompanyDaemon` verifies kernel peer identity on the UDS socket via `LOCAL_PEERCRED` + `LOCAL_PEERPID` (macOS) or `SO_PEERCRED` (Linux). When `sourdough client-web` bridges browser HTTP requests over UDS, all connected browser tabs collapse onto the bridge process's PID. Consequently, `client-web` must be typed by the control plane as a bridge-proxied local session (`session_class = "bridge_session"`): it defaults to `board_viewer`, requires explicit local-launch principal binding (`board_binding`) and bridge-enforced user confirmation to exercise `board_control`, and never masquerades as a hardware-backed native signer with `presence_evidence_ref`.

### 2.2 Probe-gated desktop WebView option (`zero://app`)

Reusing `apps/board/` (Native SDK `0.11.1`) as a desktop WebView host loading the same React 19 `@openboa/yogurt` bundle from `zero://app` is permitted **only after** passing a pre-implementation Native SDK `0.11.1` capability probe verifying:
1. System WebView availability and strict `zero://app` origin/CSP enforcement (no remote origins).
2. Bounded JS-to-Zig IPC keeping UDS socket access, `LOCAL_PEERPID` identity, and `0o600` `O_NOFOLLOW` `(company_id, principal_id)` `board-pending` persistence inside the native Zig layer rather than WebView storage.

### 4.4 Universal Inline Human-Language Confirmation (`ControlledInlineConfirm`) & `CommandOutboxPanel`

- **Universal Inline Human-Language Confirmation (`ControlledInlineConfirm` on `@ui-sdk/react/button` `SDKButton`, zero modal popups)**:
  1. Expands smoothly **in-place** inside the approval card (or below the top bar for header safety controls) without dimmed modal overlays.
  2. Rejects automated invocation (`if (details?.source === "agent") return;`) and attaches `data-agent-confirm="<consequence>"` strictly on the confirm CTA (never on cancel or secondary links).
  3. Contrasts plain-language **`What changes`** (`<dl>`) against **`What stays untouched`** (`<dl>`), states a clear consequence/risk note, uses a consequence-verb CTA (never generic `"OK"`), and captures `payload.reason` (`1..2000` chars) where required.
  4. Collapses composite optimistic preconditions (`charter_revision`, `expected_*`, `payload_sha256`, `command_id`, `lease`) inside a closed-by-default `"Technical details"` disclosure row.
  5. Collapses cleanly upon human click to hand off lifecycle tracking (`submitting -> unknown | accepted | applied | denied | not_found_retry_choice`) to the persistent inline **`CommandOutboxPanel`**.
- **Specialized Inline Safety Panels**:
  - `resume_new_risk`: Non-binding readiness check + plain explanation of server-side `15s` `QUOTE_MAX_AGE_NS` verification (zero pre-fetched client countdown).
  - `release_restore_quarantine`: 5-step **"Safe Custody Hold"** readiness checklist (`Data cut`, `Sole writer`, `Current authority`, `External reconciliation`, `Eligible next actions`).
  - `review_tool.quarantine`: Pre-computed indented DAG **Blast-Radius Tree Preview** + automatic global `revision DESC` fallback target.

*Iterative high-fidelity polish target:* Live dynamic transition animations on `Live Trading` (streaming fills, smooth KPI/chart ticks) and adaptive graph layout tuning on `Agents & Activity` are tracked as ongoing visual-craft refinements while strictly preserving `prefers-reduced-motion: reduce`.

## 6. Link state, data wipe, and host-lock privacy shield

Three failure/privacy states are strictly disjoint and must never be conflated:

1. **Transient Disconnect / Daemon Restart**: Triggers on UDS `ECONNREFUSED`, EOF, timeout, or `503`. Sets `link_state = "disconnected"`, `stale = true`, `controls_locked = true`, and keeps verified `Data State` visible beneath a calm/urgent stale `Notice` showing elapsed disconnect time. Never calls `clearData()`.
2. **Authorization Loss (`401`/`403`) or Scope/Principal Switch**: Triggers on `401`, `403`, `IncompatibleTimeline`, or change of `company_id`, `store_key`, `socket`, or `principal_id`. Executes **instant zero-grace `clearData()`**, freeing cached projection stores, wiping all sensitive DOM nodes, and resetting in-memory command state while preserving valid on-disk `board-pending` (or quarantining stale `403` pending files on startup).
3. **Host / Session Lock (`host_locked = true`)**: Triggers on OS screen lock, host idle timeout, or operator privacy lock. Mounts an **opaque full-viewport Privacy Shield** (`data-agent-hidden`) over all financial, decision, office, CEO thread, and outbox DOM (unmounting or redacting protected subtrees). Crucially, host lock **does not** alter `data_as_of_ns`, set `stale = true`, or mutate `LinkState`. Unlocking requires OS/session verification plus a fresh `GET /v1/meta` and projection confirmation before lifting the shield.
