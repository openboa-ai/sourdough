# Present client screens and navigation

Design draft · Verification **UNRUN** · Responsible component: Board Client

[Feature intent](../intent.md) · [Client architecture](../../architecture.md) · [Flow observability](../flow-observability/spec.md) · [System map](../../../README.md) · [Development lifecycle](../../../engineering/lifecycle.md)

## Boundary and dependencies

Define the complete screen inventory, route hierarchy, role visibility gates, freshness/redaction rules, and required UI states across the seven domain-derived Information Architecture areas. All screens consume authorized UDS projections (`GET /v1/meta`, `GET /v1/projections/*`, `GET /v1/events`) and route every mutation through [Command submission](../../commands/submit/spec.md).

Input contracts: [Base presentation](../present/spec.md) · [Investment evidence](../investment-panel/spec.md) · [Command submission](../../commands/submit/spec.md) · [Client architecture](../../architecture.md). These are public service contracts, not imports of service implementations.

## Design decision and review

Organize navigation inside `SidebarLayout` across seven domain areas grounded directly in Sourdough's 13 flows, anchored by a persistent Global Status & Safety Bar and an always-visible `CommandOutboxPanel` whenever `command_state !== "idle"`. Every route below separates `[Live origin/main]` data/commands from `[M3 Extension]` endpoints and schemas.

### Required UI states on every screen

Every route above must implement all five standard states consistently without layout collapse or hidden failure:

1. **`empty`**: Domain-accurate empty state explaining why no records exist yet (e.g., `"No active paper orders"`, `"No open reserved decisions"`, `"Paper profile not enabled on this core-only company"`). Never renders numeric `0` balances as stand-ins for absent profiles.
2. **`loading`**: Initial `connecting` / fetch skeleton preserving the Persistent Global Status & Safety Bar; never replaces already-verified Data State during routine background refreshes.
3. **`error`**: Explicit failure `Notice` on `incompatible` contract version, malformed payload, or `401`/`403` access denial (paired with `clearData()` on `401`/`403`/scope mismatch), showing HTTP status / `denial_code` and a retry or scope-selection action.
4. **`stale`**: Triggered on transient UDS disconnect (`link_state = "disconnected"`, `stale = true`, `controls_locked = true`). Retains last verified Data State intact beneath an urgent `Notice` displaying `as_of_ns` and disconnect duration while disabling all mutating controls.
5. **`locked`**: Two distinct sub-modes: (a) **`controls_locked`** (`bootstrap_locked`, `board_viewer`, `stale`, or in-flight `pending` / `unknown` command) keeps read projections visible while disabling command triggers with an explicit reason chip; (b) **`host_locked`** mounts the full-viewport opaque Privacy Shield (`data-agent-hidden`) over protected DOM without altering `as_of_ns` or `stale`.

## Operations and change review

New `[M3 Extension]` routes must remain hidden or clearly marked unavailable when `GET /v1/meta` omits their projection or command capability.
