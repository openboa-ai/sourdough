## Boundary and dependencies

Map all thirteen Sourdough operational flows (`01`–`13`) to exact client screens, authoritative backend sources (`[Live origin/main]` vs `[M3 Extension]`), live UDS event streaming, causal lineage chains, Desk and blindness opacity rules, and honest `Unavailable` / `Missing` states.

## Design decision and review

### 1. Live event streaming and projection refresh contract

- **Transport**: The client consumes `GET /v1/events?after_seq=<n>&limit=100&wait_ms=5000` (`application/x-ndjson`, 7-field envelopes `{event_seq, company_id, domain, entity_type, entity_id, event_type, recorded_at_ns}`) over `fetch()` streaming (never `EventSource`), paired with conditional `GET /v1/projections/{name}` using `If-None-Match` (`ETag`) and `X-Sourdough-Event-Seq` for tear-free snapshot alignment.
- **`origin/main` vs `[M3 Extension]` wakeup and `audit_event` boundary**: In `origin/main` (`src/sourdough/ipc/server.py`), `CompanyDaemon` exposes `/v1/projections/work-timeline` (`work-timeline-v1` / `work-timeline-v2`), `/v1/commands`, `/v1/commands/{command_id}?operation=...`, and `/v1/events`. Crucially, live `GET /v1/events` queries **only** `audit_event` rows in `company.sqlite` (`SELECT ... FROM audit_event WHERE company_id = ? AND event_seq > ?`), and `CompanyDaemon._event_cond` notifies waiters only on `_handle_submit_command` and `stop()` (polling `0.25s` timeout slices otherwise). While founding, checkpoint, domain-activation (`storage/schema.py`), review-tool, Flow 08 (`accounting_close.py`, `paper_funding.py`, `paper_statement_store.py`), and Flow 09 (`strategy_comparison.py`) modules (16 modules total: 15 domain modules plus `storage/schema.py`) already emit `audit_event` rows, `paper_order.py`, `paper_books.py`, `paper_account.py`, `paper_decision.py`, `paper_research.py`, `paper_reconcile.py`, `paper_resume.py`, `staffing.py`, `onboarding.py`, `conversations.py`, `conversation_delivery.py`, `work_handoff.py`, and `work_peer_response.py` currently have zero `audit_event` writes in `origin/main`, and the writerless/venue-isolated `nautilus_runtime.py` (`prepare_paper`/`supervise_paper`) and `runtime/venue_coordinator.py` (`BoundedVenueCoordinator.plan_segments()`) modules emit their runtime/segment events via the owning `CompanyRuntime` / `paper_account` / `paper_window` `write_tx` coordinator under `WriterLease`. Wiring `CompanyRuntime` writes to `_event_cond.notify_all()` and adding missing `audit_event` emissions across those 15 domain/runtime areas are explicit **`[M3 Extension]`** requirements (see [Event stream, runtime wakeups, and typed commands](../../control-plane/commands-and-events/spec.md)), alongside the domain-specific read projections below. Flow 13 (`offline-trial-registry-v1`, `trial_registry.py` + `trial_execution.py`) resides in a physically separate SQLite database outside `company.sqlite`, so evaluator completion and grade change notifications are `[M3 Extension]` via an evaluator-store feed/poll adapter rather than `company.sqlite`'s `audit_event` table. Whenever an `[M3 Extension]` projection is absent from `GET /v1/meta`, the corresponding route renders an honest unsupported-capability state without issuing unsupported requests.

### 3. Strict paper-only boundary and swappable `PaperExecution` telemetry

All trading observability and operator controls across Flows `03`, `04`, `05`, `07`, `08`, `09`, and `11` are strictly bounded to simulated paper execution:

- **Hard environment invariant**: `paper_binding.environment == "paper"` (`CHECK (environment = 'paper')`). Live brokerage/exchange credentials, live-order entry tickets, and capital deposit/withdrawal flows have zero routes, dialogs, or client state.
- **Swappable adapter decoupling**: Views rendering orders, fills, cancellations, positions, P&L, and challenger trials consume `PaperExecution` DTOs (`PaperIntent`, `PaperOrderSizing`, `VenueExecution`, `VenueCancellation`, `VenuePosition`, `PaperStatement`), independent of the concrete venue implementation (`FixedQuoteVenue`, `nautilus-spot-sandbox-v1`, `nautilus-offline-spot-replay-v1`). Swapping adapters via `change_paper_binding` updates only `/paper/adapter` metadata (`connector_revision`, `destination_id`, `BoundedVenueCoordinator` segments, `paper_sender_lease`, and `paper_binding_change.blocked_by`) and gates new order admission while draining.
