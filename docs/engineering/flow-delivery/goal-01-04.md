# 첫 Goal · 회사 기동부터 체결 직후 복구까지

다음 블록을 개발 세션의 첫 지시로 사용한다. **상태: 작성됨 / 제품 시험 UNRUN.** 이 문서를 머지하는 것은 Goal을 실행하거나 제품을 합격시키는 일이 아니다.

> /goal Sourdough의 01–04를 순서대로 구현하라. 정상 제품 진입점에서 회사가 첫 근무를 시작하고, 테스트 작업자가 근거 있는 판단을 남기고, 그 판단이 모의 주문이 되게 하라. 모의 체결이 확정된 직후 회사가 죽어도 회사 감독자가 복구하고 같은 Agent의 다음 근무가 복구된 포지션을 읽어 새 판단을 남겨야 한다. 아래 네 인수 조건, 개발 단위 PR, 최종 통합 PR의 독립 관찰과 필수 CI, main 머지 후 확인까지가 완료다. 실거래·유료 모델·외부 계정 없이 진행하고 권한이나 근거가 부족하면 해당 주장만 보류하라.

| 순서 | 해당 개발 단위 PR에서 관찰할 결과 |
| --- | --- |
| 01 · 창업 | [첫 소유 명세](../../company/systems/organization/found-company/bootstrap/spec.md)부터 시작한다. 커밋 뒤 응답 유실·재시작·같은 요청 재시도에도 회사·창업자·위임·최초 근무 ID가 동일하다. 다른 헌장으로 재사용하면 충돌하고, 기존 저장소가 사라지면 새 회사로 대체하지 않는다. |
| 02 · 첫 근무 | Client가 닫혀도 예정된 근무가 시작된다. 작업자가 시점이 있는 관측을 읽고 근거·판단·다음 조건을 남긴다. 같은 기동을 두 번 전달해도 실행 권한은 하나다. |
| 03 · 모의 체결 | 같은 판단이 한 모의 계좌의 위험 검사·예약·주문·체결·포지션으로 이어진다. 한도 초과는 전송되지 않고 중복 체결 통지로 수량·수수료가 두 번 반영되지 않는다. 승인된 NautilusTrader 설정 경로를 이때 시도한다. 사용 불가면 독립 모의 원본으로 계속하되 실제 바인딩을 합격 처리하지 않는다. |
| 04 · 장애 후 다음 근무 | **동일한 단일 실행**에서 모의 체결 원본이 확정되고 회사에 응답·통지되기 전에 회사 프로세스를 종료한다. 감독자가 기존 송신자를 차단하고 자동 재시작한다. 독립 원본과 원장에서 전송 1·체결 1·금융 반영 1, 수동 재시작 0을 대조한다. 같은 Agent의 다른 근무 ID가 복구 수량을 읽고 새 판단을 남긴다. 결과가 불명인 대조 사례에서는 재전송하지 않는다. |

**개발 루프.** 흐름 Issue 하나와 `feat/flow-01-04` 하나를 사용한다. [작업 색인](../work-packages.md)의 현재 소유 명세 → 실패가 관찰되는 시험 → 최소 제품 변경 → 다음 소비자 관찰 → 단위 PR 순서로 진행한다. 앞 단위를 건너뛰거나 번호마다 모든 하위 기능을 완성하려 하지 않는다. 같은 실패가 반복되면 새 근거를 수집하거나 의존하지 않는 작업을 계속한다. 자격증명·비용·권한 확대가 필요하거나 독립 원본이 없어 주장을 입증할 방법이 없으면 미검증 범위와 재개 조건을 남긴다.

**머지 증거.** `tests/flows/flow-01-04/test_flow.py`의 `ConnectedFlow.test_end_to_end`은 01–04를 따로 실행한 로그의 합이 아니라 위 단일 실행을 재현한다. 통합 PR에 명령, 코드 리비전, 회사·Agent·전후 근무·판단·주문·체결의 상관 ID와 대사 결과를 연결한다. 시험기는 관찰·장애 주입만 맡고 재기동·재예약·원장 수리를 하지 않는다. 테스트 작업자는 허용된 대역이며, 창업/채용 Agent 자율성(05/06), 실제 시장 기반 성과, 수익성, RSI는 이 Goal의 합격 주장이 아니다.
