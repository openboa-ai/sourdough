# Goal 01–04: the Agent's first paper trade

Status: specified, not executed. Open the [flow Issue #7](https://github.com/openboa-ai/sourdough/issues/7) for handoff. This is a working product slice, not an isolated broker demo.

> /goal Build the connected Sourdough system through its first paper trade. From the normal entry point, start the company and one employee Agent. Let that Agent submit one authorized paper order through the fund system. Stop when the paper execution destination confirms a fill and the company books show the resulting position. Deliver the development-unit PRs and the verified flow PR. Do not extend this Goal into a market-data, Agent-quality, resilience or profitability project.

| Step | Deliver one connected behavior |
| --- | --- |
| 01 · Company | Found the company with one Agent, a standing grant and a first duty. Provision the bounded paper account through the fund profile, not in company founding. Start at the [founding spec](../../company/systems/organization/found-company/bootstrap/spec.md). |
| 02 · Agent | The company's scheduler starts the duty; the harness gives the actual Agent access to the account and the order tool. A fixed test quote is sufficient. A human, Terra or the test driver must not call the order tool in the Agent's place. |
| 03 · Paper execution | The Agent requests an order. Check its grant, account, quantity and limits; record the order and reservation before dispatch. Configure and start the paper destination through the company adapter. Use the managed trading runtime where authorized; a local paper execution adapter may support the first trade, but must actually execute the order, not fabricate a fill in the company books. |
| 04 · First trade | Join one run from Agent tool request to accepted order, destination fill, book entry and resulting position. Verify the company, Agent, paper account, order and fill references and the filled quantity. **This is the finish line.** |

**Pass:** A bounded actual Agent run through the normal system produces the linked fill and position without a person placing the order. A paper price may be fixed or replayed; no live feed, second shift or second trade is required. A hold is valid behavior but not an observed trade. A mocked Agent, a standalone SDK order, a sent-but-unfilled order or a ledger fixture alone cannot pass. Record the Agent binding, pricing source, paper adapter and exact revision; do not claim a different binding was qualified.

**Delivery:** Use one Issue, one PR per development unit and one aggregate PR from `feat/flow-01-04`. CI runs the deterministic path at `tests/flows/flow-01-04/test_flow.py::ConnectedFlow.test_end_to_end`. Before merge, link the actual Agent's first-trade receipt from the same candidate. CI needs no paid model or secrets; a deterministic CI pass alone is not Agent evidence. Never use live funds or silently enable a paid model. If the authorized runtime is unavailable, finish independent wiring and report the missing evidence.

**Later, not blockers:** repeated trading, current-market paper evaluation, richer research or judgment, crash injection, automatic restart, broad reliability qualification, hiring, net-return comparison and RSI have their own milestones. Preserve paper-only routing, authority, bounded exposure and truthful books from the first trade.
