# Engineering Spec: Core Company OS Boundary Separation, Unified Trading Consolidation & Documentation Alignment (`flow-core-domain-cleanup`)

Status: Active specification (M1–M5 implemented & aligned, M6 Phase 1–2 E2E & adversarial hardening verified; Phase 3 PR delivery via `feat/flow-core-domain-cleanup` targeting `main`) · PR delivery branch: `feat/flow-core-domain-cleanup` (targeting `main`) · Owner: Core Company OS, Trading Domain Module, Board Client SPA, and Repository Documentation.

## Intent

Eliminate accumulated schema, runtime, IPC projection, UI, and documentation duplication and drift in `openboa-ai/sourdough` by:

1. **Physically separating the industry-neutral Core Company OS from pluggable business domain modules (beginning with Trading)** via explicit registration contracts (`docs/conventions.md`), so Core OS SQL schemas, runtime loops, prohibitions, risk gates, CLI commands, IPC projections, and shell chrome contain zero hardcoded trading or paper-trading assumptions.
2. **Consolidating four overlapping trading ledger generations (`paper_*`, `agent_sandbox_*`, `company_paper_*`, `trading_book_*`), three competing projections (`live-trading-v1`, `execution-tiers-v1`, `trading-desk-v1`), and duplicate UI surfaces** onto one unified 3-tier execution model (`execution_environment_binding` + `trading_book_{order,fill,position,valuation}` + `trading-desk-v1` + `order-trace-v1` + `TradingDeskView`), removing legacy `paper_*`, `company_paper_*`, and `agent_sandbox_*` duplicate tables, `live-trading-v1`, `execution-tiers-v1`, `paper-risk-command-v1`, `LiveTradingView`, and `/performance`.
3. **Resolving verified schema, runtime, and frontend mismatches**, including `decision_question.application_status = 'failed'` vs `08_board_client.sql`, `work_follow_up.purpose` `'position_review'` default in `02_company_core.sql`, `duty.state` / `work_items` alignment, `promote_live` vs `promote_to_live` in `TradingDeskView.tsx`, broken `order-trace-v1` lookups on `trading_book_order`, and stale pre-Modular-IA internal routes.
4. **Aligning `README.md`, `docs/*.md`, `docs/engineering/*`, and `docs/client/**`** to match the refactored two-layer architecture, 14 UDS projection endpoints, Modular IA routes, and 4-slot header.

## Authority & Data Boundaries

### 1. Core Company OS (`storage/schema/v1/core/`, Core Python Modules, Core SPA Shell)

- **Owned Tables (`storage/schema/v1/core/01..08.sql`):**
  - `installed_domains`: canonical `domain IN ('core', 'trading')` with `schema_version = 1`. Founding a company (`found()`) installs `'core'` only. Opt-in domain activation (`enable_domain_v1(conn, "trading")`) installs `storage/schema/v1/trading/*.sql`. `storage/schema.py` provides `canonical_domain_name(domain)` normalizing legacy `"paper" -> "trading"` for API boundary calls (`is_domain_installed`, `require_domain`, `enable_domain_v1`) while never writing `"paper"` into new stores.
  - Core kernel & company tables: `company`, `board_binding`, `role_assignment`, `decision_question`, `restriction_cause`, `duty`, `work_items`, `work_runs`, `work_responsibilities`, `work_conditions`, `work_peer_requests`, `work_follow_up`, `work_review_decision`, `staffing_*`, `onboarding_*`, `retirement_*`, `private_desk` (opaque counts only), `ceo_message`, `project_message`, `general_ledger`, `accounting_close`, `assessment_publication`, `writer_lease`, `audit_event`, `external_actions`.
  - **DDL Fixes in `core/`:**
    - `08_board_client.sql`: `decision_question.application_status TEXT NOT NULL DEFAULT 'pending' CHECK (application_status IN ('pending', 'applied', 'declined', 'not_applicable', 'failed'))`.
    - `02_company_core.sql`: remove `DEFAULT 'position_review'` on `work_follow_up.purpose` (`purpose TEXT NOT NULL`); constrain `duty.state TEXT NOT NULL CHECK (state IN ('due', 'scheduled', 'running', 'waiting', 'settled', 'incomplete', 'archived', 'handed_off'))` with authoritative mapping to `03_work_kernel.sql` `work_items.state` (`incomplete -> blocked`, `archived | handed_off -> cancelled | settled`).
- **Core Boundary Invariant:**
  - Zero files in Core Company OS (`storage/` except domain-agnostic ownership/schema registries, `company.py`, `staffing*.py`, `onboarding.py`, `retirement.py`, `assessment_run.py`, `hiring_run.py`, `duty_run.py`, `first_duty.py`, `work*.py`, `abandoned_work.py`, `employee_process.py`, `board_control.py`, `company_restore.py`, `runtime/`, `ipc/`, `cli.py`) may import any trading module (`trading/*`, `execution_tiers`, `paper_*`, `first_trade`, `strategy_comparison`, `trading_engine`, `nautilus_*`, `market_*`, `binance_*`) or embed hardcoded `"paper"`, `"Quant"`, `"position_review"`, or `'execution:paper'` assumptions.

### 2. Core ↔ Domain Extension Contract (8 Typed Seams)

Core runtime, IPC, and CLI expose a typed `DomainPlugin` / `DomainModule` registration contract (`sourdough/runtime/domains.py`) wired at composition roots (`cli.py`, `ResidentCompanyService`, `CompanyDaemon`):

1. **Duty Handlers & Preconditions (`DutyRegistry`):** Domains register `DutyDescriptor` entries (e.g., `trading.agent_sandbox`, `quant.agent_sandbox`, `quant.paper_decision`, `quant.reconcile`) with explicit `required_scope` and domain-owned preconditions. Core `runtime/__init__.py` and `runtime/handlers.py` register only `ceo.respond_message` and `board.apply_decision`.
2. **Agent Tool Specs & Handlers (`ToolContributor`):** `OuterToolBroker` dynamically contributes domain tools when `is_domain_installed(db, domain)` holds, rather than hardcoding trading/sandbox tools in `_CEO_READONLY_TOOLS` or `_SANDBOX_TOOL_SPECS`. Missing `standing_grant` raises `RuntimeRefused` (fail closed) instead of defaulting `grant_scope = "paper"`; missing `agent_profile.role_label` defaults to `"Agent"` instead of `"Quant"`.
3. **Board Decision Action Handlers (`DecisionActionRegistry`):** `_run_board_apply_decision` executes core actions (`update_agent_budget`, advisory) and dispatches domain actions (`open_agent_sandbox`, `migrate_paper_to_live`) to handlers keyed by `impact["action"]`. All registered handlers execute inside a uniform `try/except` boundary that catches domain refusals (`DomainActionRefused` / `ExecutionTierRefused`) and durably records `application_status = 'failed'` via `board_control.record_decision_application_result` (which validates `application_status` and `delivery_status` enums before writing SQLite).
4. **Restore Reconciler & Pre-Check Hook (`RestoreDomainGuard`):** `company_restore.py` accepts `domain_guards: Mapping[str, RestoreDomainGuard]`. If an active installed domain lacks a registered reconciler, `restore_core_checkpoint` fails closed generically (`f"Domain '{domain}' requires an independent restore reconciler"`), removing hardcoded `"paper"` checks.
5. **Abandoned-Work Committed-Result Predicates (`CommittedResultPredicate`):** `abandoned_work.py` checks core `assessment_publication` and `work_review_decision`, plus registered domain predicates `(conn, tables, duty_id) -> bool`. Trading registers its unified `trading_book_order` / domain-decision predicate when active, removing `paper_research_decision`, `paper_decision`, and `paper_order` references from `abandoned_work.py`.
6. **Work / Duty Purpose & Onboarding Scope (`WorkDomainPolicy`):** `PAPER_EXECUTION`, `POSITION_REVIEW`, `FIRST_DUTY_SCOPE`, and `require_paper_authority` move out of `duty_run.py`, `first_duty.py`, `work.py`, and `onboarding.py`. Core `work.py` / `onboarding.py` accept explicit `purpose` and registered `(purpose -> scope)` mappings (with core registering `assessment`). `employee_process.py`, `assessment_run.py`, and `hiring_run.py` decouple onto Core error classes (`EmployeeProcessRefused` / `DutyRefused`, removing all `from .first_trade import TradeRefused` imports) and generic `run_first_duty_exchange(...)` instead of `"paper_buy"`.
7. **Core Governance Authorization & Process Independence:** `AuthorizeBoard` moves out of `paper_risk.py` into `board_control.py` (breaking `.paper_risk` imports in `board_control.py`, `runtime/resident.py`, `ipc/server.py`, `ipc/projections.py`). `BoundedVenueCoordinator` / `VenueSegment*` and `venue: PaperExecution` move out of `runtime/venue_coordinator.py` and `runtime/engine.py:run_bound_handler`, replaced by a generic `IndependentProcessGuard` protocol (`require_independent_from(store: Path) -> None`). `STRATEGY_COMMAND` (`execute_strategy_command`) moves out of `board_control.py` into a Trading-registered command handler.
8. **Projections, IPC Server, `/v1/meta`, and CLI Contributions:**
   - `work_projection.py`: Core emits `duties` + `work_review_decision` and delegates optional `domains[name]` payload enrichment to active domain contributors.
   - `ipc/server.py` & `ipc/projections.py`: Core serves core projections and core commands (`SEND_CEO_MESSAGE`, `SUBMIT_DECISION_ANSWER`, `PAUSE_COMPANY`, `RESUME_COMPANY`, `INTERRUPT_RUN`, `CANCEL_WORK`, `CUT_CHECKPOINT`, `REGISTER_OWNER`). Trading registers domain projections (`trading-desk-v1`, `order-trace-v1`, `strategies-v1`) and domain commands (`EXECUTION_TIER_COMMAND`, `STRATEGY_COMMAND`, `execution:*` risk controls), advertised in `_supported_commands()` and accepted in `_dispatch()` **only** when `"trading"` is installed (`422` otherwise). `/v1/meta` drops `paper_risk_suspended` and `paper_risk_effective_revision`, emitting `active_domains` and `active_restrictions_count`.
   - `cli.py`: Core CLI registers company OS commands; Trading registers its CLI subcommands via `register_cli_subcommands(subparsers)`.

## Allowed & Prohibited Behavior

- **Allowed:**
  - Founding, booting, operating, checkpointing, and restoring a core-only company (`installed_domains = {'core'}`) with zero trading tables, zero trading CLI/IPC commands, `/agents` default landing route, neutral safety/agent status text, and generic restore reconciler checks.
  - Installing the Trading domain module to execute isolated Tier 1 `agent_sandbox`, `N >= 1` concurrent Tier 2 `company_paper` books, and Board-approved Tier 3 `company_live` execution through unified `execution_environment_binding` and `trading_book_*` tables.
  - Recording `decision_question.application_status = 'failed'` cleanly when `board.apply_decision` catches a fail-closed domain refusal (`ExecutionTierRefused` / `DomainActionRefused`).
  - Rendering `environment_promotion_record.action === 'promote_live'` as a success event in `TradingDeskView` and tracing both `paper` and `live` `trading_book_order` records via `OrderTraceView`.
- **Prohibited:**
  - Importing Trading Python modules or referencing trading tables/identifiers (`paper_*`, `company_paper_*`, `agent_sandbox_*`, `"Quant"`, `'execution:paper'`, `"paper-only"`) inside Core Company OS modules, core SQL packs, or core UI shell components.
  - Retaining duplicate legacy trading tables, dual-writes (`company_paper_*` + `trading_book_*`, `duty`/`duty_run` split writes), removed projections (`live-trading-v1`, `execution-tiers-v1`), or removed views (`LiveTradingView.tsx`, `/performance`).
