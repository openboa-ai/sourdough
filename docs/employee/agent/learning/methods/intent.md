# Turn an observed mistake into a tested improvement

Design draft · [Evaluation and institutional memory](../README.md) · [Company MVP map](../../../../README.md) · [Development lifecycle](../../../../engineering/lifecycle.md)

Business situation: [Improve a method](../../../../capabilities.md#learning).

## Operating need

The company should remember mistakes and measure whether a change helps a later Agent make better judgments.

## Observable outcome

A scoped memory or skill candidate cites a witnessed episode, is compared with the incumbent and is adopted only within a distinct promotion grant. A fresh Agent shift must use the adopted revision; rollback is observable on a later shift. See [L1](../../../../acceptance/episodes.md#l1-learning).

## Scope of discretion

Agents propose changes during a review or idle-time dreaming. Policy and risk grants remain controlled by the authority service.

A change may target either a work method or the procedure used to diagnose and produce better work methods. Record which one changed. Only the [recursive learning comparison](../../../../acceptance/recursive-learning/spec.md) tests the second claim; it is independent of any business profile.

Functional verification, economic performance and transfer of an improvement procedure have distinct owners and verdicts. A candidate memory or persuasive explanation is not itself recursive improvement; this document specifies evaluation rather than claiming an implemented RSI capability.
