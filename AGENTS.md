# Working on Sourdough

Write repository documentation in English. Use the [glossary](docs/glossary.md) for domain terms. The development model implements Sourdough; the employee Agent makes the trading decision. No development plugin is required.

1. Read the [first Goal](docs/engineering/flow-delivery/goal-01-04.md), [roadmap](docs/engineering/development-roadmap.md) and the [owning spec](docs/engineering/work-packages.md) for the current change.
2. Follow the [implementation and review guide](docs/engineering/flow-delivery/guide.md). Give each observable change its own PR; the flow Issue links the constituent PRs.
3. Apply the [delivery contract](docs/engineering/flow-delivery/spec.md) and [contribution rules](CONTRIBUTING.md). Never infer permission, a product pass or delivery from a label, a branch or a green CI badge.
4. When opening a ready PR authorized for delivery, request [automatic squash merge](docs/engineering/flow-delivery/guide.md#automatic-merge) rather than handing the merge button to the user.
